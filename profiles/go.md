# Bits’s Go Profile V0.3

> 正确 > 清晰 > 可修改 > 一致 > 简短

底层目标：**让代码和逻辑简单到不容易出错。**

本 Profile 不重复检查 `gofmt`、Go 编译器和基础 lint 已覆盖的问题。格式、未使用导入、未使用变量、不可达代码和依赖环由工具链处理；Bits 关注错误路径、状态、资源、并发和抽象成本。

## 1. 工具边界

- 格式统一使用 `gofmt`，import 整理使用 `goimports`，不做人工格式评审。
- 基础正确性使用 `go vet`、编译器和 `staticcheck`。
- 并发变更使用 `go test -race`。
- 不为了 Bits 的风格重复实现上述检查，不把 formatter 输出差异当成语义问题。

## 2. 正确性优先

### GO001　错误路径必须显式存在

- `error` 放在最后一个返回值。
- 每个错误必须被处理、转换、包装或显式丢弃，禁止静默忽略。
- 使用 `errors.Is/As` 判断错误，使用 `%w` 保留错误链。
- 普通失败不得使用 `panic`；库代码不得使用 `log.Fatal` 或 `os.Exit` 代替返回错误。
- 清理路径确实需要忽略错误时，使用 `_ = close()` 等显式写法，不允许隐藏空分支。

### GO002　资源获取后立即确定释放路径

- 获取资源后紧接着使用 `defer` 释放，避免在多个分支重复释放。
- `defer` 的求值时机、接收者、参数和错误处理必须明确。
- 不使用 `goto` 组织清理逻辑。
- 获取与释放必须在同一所有权层级，不能把释放责任隐式转嫁给调用方。

### GO003　取消与生命周期必须显式

- `context.Context` 作为第一个参数传递，不存入 struct，不放入全局变量。
- 启动 goroutine 时必须能回答：谁等待它结束、谁负责取消、如何退出、如何回收资源。
- 长任务必须处理 `context.Done()` 或具有明确的非取消契约。
- 不使用无法关闭的 channel、无法退出的 ticker 或没有终点的后台循环制造永久泄漏。

### GO004　共享状态必须有唯一所有权

- 优先通过 channel、不可变消息或明确的所有权转移避免共享可写状态。
- 必须使用共享可写状态时，明确由 mutex、channel 或单 goroutine 所有权保护。
- 不复制 mutex、WaitGroup 或包含它们的值；锁使用完成后立即 `defer` 解锁。
- 禁止依赖“通常不会同时访问”的隐式并发假设。

## 3. 清晰优先

### GO005　主流程保持靠左

- 使用 guard clause 处理错误和异常路径。
- `return` 后不保留无意义的 `else`。
- 优先通过数据表、枚举和统一零值消除特殊情况，不连续增加补丁分支。
- `if err := f(); err != nil`、`if v := f(); cond` 等结构化条件初始化是允许的，不属于禁止的条件内赋值。
- 扁平 `switch` 不因为 case 数量被视为复杂；分支内部继续嵌套判断才增加复杂度。

### GO006　让零值和数据结构表达约束

- 优先让类型的零值可以直接使用，减少强制初始化和 nil 特殊分支。
- 使用类型、枚举和小数据结构表达状态，不使用无约束的字符串和布尔组合模拟状态机。
- 无法表达的状态不需要防御性判断；非法状态尽量在类型和构造函数边界排除。
- 不用 `map[string]any` 代替边界清晰的数据结构。

### GO007　复杂度约束针对逻辑，不针对屏幕

- 函数有效代码行、嵌套和圈复杂度遵循 BCS003，但不得为达标拆散一个连续决策过程。
- 参数不超过 4 个，禁止布尔参数切换行为。
- 参数重赋值、变量遮蔽和可变全局状态会放大理解成本，禁止新增。
- 不为了缩短代码使用嵌套表达式、双重否定或高密度 one-liner。

## 4. 可修改性优先

### GO008　依赖显式传递

- 禁止可变全局、Singleton 和有副作用的 `init()` 隐式注入依赖。
- 配置、时间、随机数、存储和外部服务通过参数或构造函数传入。
- 不在包级别保存当前请求、当前用户或当前 context。

### GO009　接口由使用方定义

- 接口只包含调用方实际需要的方法，通常保持 1–3 个方法。
- 默认返回具体类型；只有确实需要多态时才返回接口。
- 只有一个实现的接口只有在进程边界、外部系统、插件或测试替身等真实接缝存在时才保留。
- 不增加只有转发、没有新增语义的 wrapper/service/manager 层。
- 不为假想需求提前抽象；重复模式稳定后再提取。

### GO010　组合不隐藏行为

- 优先组合和显式委托，不通过深层嵌入制造隐式 API。
- 嵌入不能仅用于少写几行转发代码；嵌入后暴露的每个方法都必须是模块愿意承担的契约。
- 继承式层次不适用；不要用类型嵌入模拟深继承。

## 5. 一致性但不增加格式负担

- 导出标识符使用 `PascalCase`，未导出标识符使用 `lowerCamelCase`，这是 Go 的 API 语义，不改成 snake_case。
- 常量不强制 `UPPER_SNAKE_CASE`，遵循 Go 的导出规则和包内惯例。
- 命名表达领域含义、单位和肯定式布尔语义；禁止匈牙利命名。
- package 名保持简短、小写且与目录用途一致，不使用 `util/common/base` 收容无关概念。
- dot import 默认禁止；blank import 只允许明确的驱动或注册场景，并在引入处说明副作用。

## 6. 简短排在最后

- 不通过删错误处理、删必要注释、拆散逻辑或压缩表达式换取行数。
- 最简单可工作的实现优先于通用框架。
- 没有真实变体时不建立抽象；没有实际收益时不增加依赖。
- 代码是否能被删除，比代码是否能被写得更短更重要。
